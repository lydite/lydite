# v0.4.1 — a command component beside its own package.json gets the provisioned Node and pnpm

A component declared with `command:` and no `runner:`, whose own directory holds a `package.json`,
failed its node install with `pnpm: not on PATH — lydite could not provision it` on any machine
without an ambient pnpm. lydite installed the component's dependencies but never provisioned the
Node or the package manager that install needs, because the component declares no language. It now
does: such a component is resolved through the workspace's Node — `engines.node`, `.nvmrc` and the
`toolchain.node` override — and its `packageManager` pin, exactly as a TypeScript component is, and
its command runs with those ahead of your `PATH`.

**What a consumer sees.**

- The install succeeds where it failed, provided provisioning succeeds. If the download fails —
  offline, a registry outage, `toolchain.enabled: false` — the run continues with what is on `PATH`
  under a warning, and without an ambient pnpm the install still fails with `pnpm: not on PATH`,
  the warning above it.
- Two packages under one workspace root pinning different `engines.node` still error.
- `lydite review` and `lydite scan` are unchanged.

## If you worked around it: delete the `typescript.install` override

A repository that set `typescript.install` in `.lydite/config.yml` only to get past this failure no
longer needs it. Delete the override so the component takes the same frozen, coalesced install as
every other component on its workspace root. Keep it only if you set it to run something other than
the standard install.
