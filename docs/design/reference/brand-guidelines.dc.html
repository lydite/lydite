Brand guidelines

What lydite is, how it speaks, and the rules that keep it recognisable across a terminal, a pull request and a billboard.

01

What lydite is

Unified code-quality and security scanning for Rust, TypeScript, and Go — one CLI, run identically locally and in CI, so “green locally” and “green in CI” can never drift apart.

THE PROMISE One binary, one ruleset, one answer The same version and the same ruleset hash produce the same verdict on a laptop and on a runner. Parity is the product, not a feature of it.
THE SCOPE Coverage, static analysis, CRAP Three languages, three checks, one report. Not a linter aggregator with a UI on top — a single gate a team can agree to.
THE CHARACTER Technical, precise, trustworthy Modern without being playful. lydite states facts and thresholds. It does not celebrate, scold, or guess.
02

Name & tagline

THE NAME lydite
✓ Always lowercase, in running text and in headlines. ✓ Lowercase at the start of a sentence too. Reword if it reads badly. ✗ Never Lydite, LYDITE, or Lydite.io. ✗ Never as a verb. You run lydite; you do not “lydite” a repo.
THE TAGLINE Coverage. Quality. Confidence.
✓ Locked wording, locked order, three full stops. ✓ Only under the wordmark, or alone as a closing line. ✗ Never as a page headline or a button label. ✗ Never joined with the product one-liner in the same block.
03

Voice

Four principles. Each one has a sentence lydite would write and one it wouldn’t.
State the numberA threshold and a measurement beat an adjective.
SAYCoverage is 87%. The gate is 80%.
DON’TGreat coverage! You’re crushing it.
Name the next actionEvery failure ends in something the reader can do.
SAY3 critical findings block this merge. Fix them, or baseline them with a reason.
DON’TScan failed. Please review the output above.
Never blame the developerThe code has a finding. The person is not the finding.
SAYThis branch of merge() has no test.
DON’TYou forgot to test this function.
Say why it’s identicalParity is claimed with evidence: version and ruleset hash.
SAYSame as CI run #4821 — v2.4.1, ruleset 7f2ac9.
DON’TYour local results should match CI.
04

Copy mechanics

WORDS WE USE
finding — one result from one rule. Not “issue”, not “error”. gate — the threshold a scan must clear. Gates pass or fail. scan — one execution. Scans complete; they don’t “succeed”. baseline — an accepted pre-existing finding, always with a reason. parity / drift — local and CI agreeing, or not. ruleset hash — the identity of a configuration. Six hex characters.
MECHANICS
Sentence case everywhere — headings, buttons, table headers, toasts. Percentages carry no decimals: 87%, not 87.4%. Counts are digits from zero: 0 issues, 3 findings. Paths, commands, rules and hashes are always monospace. Severity words are lowercase in prose, uppercase only inside a badge. No exclamation marks. No emoji. Ever.
ERROR & FAILURE PATTERN — WHAT / WHY / WHAT NOW
gate failed · coverage 74% < 80%
4 files added 212 uncovered lines.
run `lydite cover --explain` to see them
What — the verdict and the two numbers that produced it. Why — the smallest true explanation, one line. What now — a command or a link. Never a full stop after a command.
05

Colour & the gradient

Full tokens live in 02 Design system.
#6E21F3 → #251FF7 · 135°
✓ Brand moments: marketing hero, empty states, the primary CTA, the mark itself. ✗ UI chrome stays flat — nav, cards, tables, badges, panels use solid tokens. ✗ Never behind body copy, never as a card fill, never two gradients on one screen.
WHAT EACH COLOUR MEANS
Violet is lydite itself — brand, interaction, the neutral data series. Teal means a gate passed. Nothing else. Amber means attention, including drift between local and CI. Rose means blocked. It appears only when something cannot merge. Navy is the substrate — the base slab of the mark, the ink of light mode.
